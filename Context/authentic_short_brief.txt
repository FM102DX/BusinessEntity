Вот короткое саммари нашего плана интеграции.

# Контекст

* Ты пишешь решение на **ASP.NET Core / C# / Blazor Server**.
* **IdP/OAuth2/OIDC-провайдер** в системе — **Authentik**, поднятый в Docker рядом с твоими сервисами.

# Роль Authentik в системе

* **Единая точка аутентификации (IdP)**: хранит пользователей/группы, показывает свою форму логина (логин/пароль, MFA, соц.логины).
* **Выдаёт токены**: после успешного входа выпускает **ID/Access JWT** и отдаёт их в твой Blazor-приложение.
* **Источник клеймов**: через **Property Mappings** формирует нужные claims (напр. `roles` из групп).

# Как подключается в Blazor и API

* **Blazor Server (интерактивный UI)**: классический **OIDC Authorization Code + PKCE**.
  Приложение не рисует форму — делает `Challenge()` → редирект на Authentik → получает токены.

  ```csharp
  builder.Services.AddAuthentication(o => {
      o.DefaultScheme = CookieAuthenticationDefaults.AuthenticationScheme;
      o.DefaultChallengeScheme = OpenIdConnectDefaults.AuthenticationScheme;
  })
  .AddCookie()
  .AddOpenIdConnect(o => {
      o.Authority = "https://auth.host/application/o/mall2-oidc/";
      o.ClientId = "mall2-client";
      o.ClientSecret = "…";
      o.ResponseType = "code";
      o.SaveTokens = true;
      o.GetClaimsFromUserInfoEndpoint = true;
      o.Scope.Add("openid"); o.Scope.Add("profile"); o.Scope.Add("email"); o.Scope.Add("roles");
      o.TokenValidationParameters.RoleClaimType = "roles";
  });
  ```
* **REST-микросервисы**: принимают **Bearer JWT** от Blazor и валидируют по JWKS Authentik.

  ```csharp
  builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(o => {
      o.Authority = "https://auth.host/application/o/mall2-oidc/";
      o.Audience  = "mall2-api";
    });
  ```

# Как настраивается «с нуля» (без ручных кликов)

1. **Docker + .env**: поднимаешь Authentik в compose; генеришь секреты (.env).
2. **Bootstrap переменные** (для первого запуска):
   `AUTHENTIK_BOOTSTRAP_EMAIL`, `AUTHENTIK_BOOTSTRAP_PASSWORD`, `AUTHENTIK_BOOTSTRAP_TOKEN` — пропускают initial-setup и выдают одноразовый API-токен.
3. **Blueprints (конфигурация-как-код)**: монтируешь папку `/blueprints` в `worker`. При старте:

   * создаётся локальный админ **mall-admin** и нужные **группы** (напр. `mall-admins`, `mall-users`);
   * заводится **OIDC Provider** (`mall2-oidc`) с явными **Redirect URI** и **ClientId/Secret**;
   * добавляется **Scope/Property Mapping** для клейма `roles` (список групп в токене);
   * создаётся **Application** (плитка) для быстрого входа.
4. **Клеймы**: в токены входят стандартные (`sub`, `email`, `name`) и кастомный `roles` (из групп). В ASP.NET можно требовать роль политикой:

   ```csharp
   options.AddPolicy("DevOnly", p => p.RequireClaim("roles", "Developers"));
   // или через Roles, если RoleClaimType="roles"
   ```

# Итог

* **Authentik** берёт на себя логин/пароль/MFA/соц.логины и выпуск токенов;
* **Blazor** лишь инициирует OIDC и получает готового `ClaimsPrincipal`;
* **API** доверяют токенам Authentik;
* **Первичная настройка** полностью автоматизируется через **Bootstrap env + Blueprints**, так что у разворачивающего систему всё работает сразу без ручных шагов.
