# Политика таблиц в Rich Document

## 1. Назначение

Этот документ фиксирует текущую политику работы с таблицами в `RichTextDocument`.

Таблицы являются частью rich-text содержимого документа и сохраняются внутри chunk storage вместе с остальными блоками документа.

## 2. Пользовательская функциональность

В режиме редактирования пользователь может:

- вставить таблицу `m*n` через кнопку таблицы на toolbar;
- вводить текст в ячейки таблицы;
- добавить строку после текущей строки;
- удалить текущую строку или выделенные строки;
- добавить столбец после текущего столбца;
- удалить текущий столбец или выделенные столбцы;
- удалить текущую таблицу;
- включить или выключить оформление первой строки как заголовка;
- включить или выключить автоматическую нумерацию строк.
- менять ширину столбцов мышкой за внутренние границы столбцов.

Текущий toolbar:

```text
[table] [TH] [№] [R+] [R-] [C+] [C-] [delete]
```

Где:

- `table` - вставка новой таблицы;
- `TH` - toggle заголовочной строки;
- `№` - toggle нумерации строк;
- `R+` - добавить строку;
- `R-` - удалить строку;
- `C+` - добавить столбец;
- `C-` - удалить столбец;
- `delete` - удалить таблицу.

## 3. Вставка таблицы

Вставка таблицы выполняется в активном Tiptap editor текущего чанка.

Пользователь задает размер таблицы в формате:

```text
3x3
```

Размер парсится как:

```text
rows x columns
```

Если значение не указано или не распознано, используется дефолтный размер.

Таблица вставляется в текущую позицию курсора.

## 4. Заголовочная строка

Кнопка `TH` является устойчивым toggle.

Если курсор находится в таблице и `TH` включается:

- первая строка таблицы переводится в header cells;
- ячейки первой строки получают визуальное оформление заголовка;
- фон первой строки светло-серо-фиолетовый;
- текст первой строки жирный.

Если `TH` выключается:

- первая строка возвращается к обычным cells;
- оформление заголовка снимается.

Визуальное правило:

```text
th {
    background: #f1effa;
    font-weight: 700;
}
```

## 5. Нумерация строк

Кнопка `№` является устойчивым toggle.

Если нумерация включена:

- в таблицу добавляется первый служебный столбец;
- ячейки этого столбца помечаются атрибутом `data-rich-table-row-number="true"`;
- таблица помечается атрибутом `data-rich-table-row-numbers="true"`;
- служебный столбец визуально отделяется от обычных данных.

Правило нумерации:

```text
если TH включен:
    первая строка служебного столбца = "№"
    строки данных нумеруются с 1, начиная со второй строки

если TH выключен:
    все строки нумеруются с 1, начиная с первой строки
```

При добавлении или удалении строк нумерация должна пересчитываться.

При переключении `TH` нумерация также должна пересчитываться, потому что меняется строка, с которой начинается счет.

## 6. Хранение

Canonical storage таблицы находится не в `HtmlCache`, а в JSON данных чанка.

Таблица хранится как отдельный блок `RichTextBlock`:

```json
{
  "kind": "table",
  "html": "<table data-rich-table-row-numbers=\"true\"><tbody><tr><th data-rich-table-row-number=\"true\">№</th><th>...</th></tr></tbody></table>"
}
```

Поле `Html` table-блока содержит sanitized table HTML.

Разрешенная структура:

- `table`
- `thead`
- `tbody`
- `tfoot`
- `tr`
- `td`
- `th`
- `p`
- `br`
- `strong`
- `em`
- `u`
- inline image marker
- inline video marker

Разрешенные table attributes:

- `data-rich-table-row-numbers` на `table`;
- `data-rich-table-row-number` на `td` / `th`;
- `data-colwidth` на `td` / `th`;
- `colspan` на `td` / `th`;
- `rowspan` на `td` / `th`.

Произвольные стили и произвольные HTML-атрибуты таблицы не считаются canonical storage и не должны сохраняться.

## 6.1. Ширина столбцов

Ширина столбцов меняется мышкой в режиме редактирования.

Правила:

- resize доступен только на внутренних границах столбцов;
- левая внешняя граница таблицы не является resize-handle;
- правая внешняя граница таблицы не является resize-handle;
- resize-handle не должен менять высоту строк и layout таблицы при hover;
- несколько resize операций подряд должны работать в одной edit-сессии.

Canonical storage ширин:

```html
<td data-colwidth="240">...</td>
```

Для colspan допускается список:

```html
<td colspan="2" data-colwidth="120,180">...</td>
```

`data-colwidth` является whitelist-атрибутом. При построении readonly `HtmlCache` значение может рендериться как безопасный derived `width/style`, но этот derived style не является canonical storage.

## 7. Сохранение

При сохранении edit chunk:

```text
Tiptap HTML
    -> HtmlToRichTextBlocksConverter
        -> RichTextBlock(kind = table, html = sanitized table html)
            -> RichTextChunkStorageSerializer.SerializeChunkData
                -> BusinessEntityDataChunks.Data
```

Таблица не должна разворачиваться в набор параграфов.

Это критичное правило:

```text
table/tr/td/th должны переживать save -> reload -> edit roundtrip.
```

## 8. Просмотр

В режиме просмотра таблица строится из `BusinessEntityDataChunks.HtmlCache`.

`HtmlCache` не является canonical storage, но должен восстанавливаться из `RichTextBlock(kind = table)`.

Правило:

```text
RichTextBlock(kind = table)
    -> RichTextChunkStorageSerializer.BuildHtmlCache
        -> <table>...</table>
```

Readonly viewport должен отображать таблицу так же, как edit viewport:

- таблица занимает доступную ширину центральной области;
- границы ячеек видимы;
- заголовочная строка оформляется как в редакторе;
- служебный столбец нумерации оформляется как в редакторе;
- inline images и inline videos внутри ячеек отображаются как inline content.

Так как readonly HTML вставляется через `MarkupString`, стили viewport должны учитывать Blazor CSS isolation и пробивать внутрь generated markup через `::deep`.

## 9. Plain text и поиск

Для table-блока plain-text строится из текста ячеек.

Назначение:

- поиск по документу;
- статистика символов чанка;
- backup/human-readable fallback.

Правило:

```text
каждая строка таблицы -> отдельная строка plain text
ячейки внутри строки -> соединяются пробелом
```

## 10. Backup / human-readable export

Human-readable export `RichTextDocument` должен сохранять таблицу как HTML table.

В export HTML должны быть стили для:

- `table`;
- `td`;
- `th`;
- `data-rich-table-row-number`.

Таблица не должна экспортироваться как набор строк обычного текста.

## 11. Ограничения текущей версии

Текущая реализация является базовой.

Поддерживается:

- вставка таблицы;
- текст в ячейках;
- базовые операции строк и столбцов;
- заголовочная строка;
- нумерация строк;
- изменение ширины столбцов мышкой;
- сохранение/перечитывание таблицы;
- просмотр таблицы;
- inline images/videos внутри ячеек как часть HTML table content.

Пока не поддерживается как отдельная пользовательская функция:

- merge/split cells;
- сортировка таблицы;
- формулы;
- стили отдельных ячеек;
- выделение произвольного диапазона с отдельным UI-командами;
- таблицы как отдельные бизнес-энтити.

## 12. Инварианты

Запрещено:

- хранить таблицу внутри paragraph HTML;
- превращать таблицу в plain text при сохранении;
- считать `HtmlCache` editable canonical format;
- сохранять произвольный unsanitized table HTML;
- загружать весь rich-document целиком ради обработки таблиц.

Обязательно:

- таблица является отдельным `RichTextBlock`;
- таблица сохраняется в текущем чанке;
- изменения таблицы делают чанк dirty;
- сохранение таблицы создает новую версию чанка и документа по общей политике версионирования;
- readonly и edit режимы должны быть визуально согласованы.
